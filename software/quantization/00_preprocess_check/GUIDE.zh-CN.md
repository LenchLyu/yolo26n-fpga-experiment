# 第 0 步：核对模型输入图像

量化前需要先确定模型会收到哪些像素。当前硬件和 Ultralytics 都要得到 640×640 图像，但缩放方法不同；如果校准与实际硬件使用不同输入，就难以判断量化带来的精度变化。

## 输入与处理

1. 读取一张 1280×720 RGB 图片。也可读取 16:9 的大图；脚本会先用 OpenCV 线性缩放得到 1280×720 的相机输入替代图，并在报告中注明。
2. 按当前 RTL 规则生成预期图：只取偶数行和偶数列，形成 640×360；上下各补 140 行 `(114,114,114)`，形成 640×640。
3. 用本机 Ultralytics `LetterBox(auto=False)` 生成固定 640×640 的软件参考图。它保留宽高比，用线性插值缩放，并补同样的灰边。
4. 若给出 `--sim-hex`，读取 XSim 实际输出，与 RTL 规则生成的图逐像素比较；另外比较 RTL 图与软件参考图。
5. 保存预览 PNG、洋红色差异图和 `report.json`。差异图中洋红色表示至少一个颜色通道不同，黑色表示三个通道全都相同。

## 运行方法

先进入 `yolo26n/` 仓库根目录，再执行：

```powershell
python .\software\quantization\00_preprocess_check\check_preprocess.py --image .\project_1\testdata\axis_resize_input_1280x720.png --sim-hex .\project_1\testdata\sim_output_rgb.hex
```

脚本默认按当前灰边 114 检查。`--rtl-pad 0` 可重现旧版黑边逻辑，但要配合旧版对应的仿真输出。`--out` 可指定独立结果目录，避免覆盖之前的报告。

## 当前结论

- 新版 XSim 输出与当前 RTL 预期 **409,600 个像素完全一致**。
- 灰边区域共 179,200 个像素，与固定 640×640 软件参考一致。
- 合成测试图仍有 44,332 个像素不同，占整帧 10.8232%。
- 真实验证帧示例先从 1920×1080 缩到 1280×720；其图像区域有 117,389 个像素不同，平均每通道绝对差为 0.9459/255。

剩余差异来自图像区域的偶数像素取样与线性插值。不同像素的数量**不能直接代表检测精度损失**。下一步应在完整验证集上比较两种预处理的检测指标，再确定校准数据要使用的处理方式。

Ultralytics 的普通 `predict()` 对单张 16:9 `.pt` 图片默认可能使用矩形输入，此环境得到 640×384。本工程的软件参考固定为 640×640，因此推理时明确设置 `rect=False`。
