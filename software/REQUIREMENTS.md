# 软件侧需求与验收条件

这份文件记录当前已经确定的输入约定，以及开始量化和 NPU 设计前需要完成的验证。实现细节变化时，以实际 RTL、脚本和测试结果同步更新这里。

## 1. 当前系统边界

- 数据源：PS 管理的 DDR 中存放一帧 1280×720、RGB888 图像；AXI VDMA 的 MM2S 通道把它作为 AXI4-Stream 送到 PL。
- 已实现的 RTL：从输入中选取偶数行和偶数列，得到 640×360，再在上下各补 140 行 RGB `(114,114,114)`，输出 640×640、RGB888。
- 流标记：输出 `TUSER` 标记帧首；每行最后一个像素使用 `TLAST`。
- 当前还没有把 RGB888 图像转换为模型所需张量，也没有 PE/NPU 推理链路。
- 最终要求：从模型输入张量到检测框输出的全部推理计算都在 PL 中实现；PS 或电脑可以负责装载图像和权重、启动运行、读取和显示检测框，但不能代算任一模型层或检测后处理。
- 目前没有开发板。可交付的验证证据是完整推理的行为仿真输出检测框，以及面向目标器件的综合、实现和时序报告；这些证据不能替代实板运行结果。

## 最终演示目标（2026-10-08 更新）

- 开发板最终须在不依赖 PC 推理的情况下独立输出检测框；目前尚无实体开发板，因此板上启动、I/O、时序和实际性能都不能宣称已验证。
- 建议先做最小功能闭环：PS 从 DDR 取得 PL 预处理结果，在板上执行完整模型推理并输出检测框。用户允许检测精度略低；尚未确定帧率要求，现阶段暂停为提高少量精度而继续优化量化。
- 当前 Vivado 设计的 VDMA 仅启用 MM2S 读通道，尚未启用 S2MM 写通道；若 PS 要读取 PL 的 640×640 输出，需要补上 AXI4-Stream→DDR 返回路径，或采用等效的数据回传方式。
- 卷积 PE 可作为后续 PL 加速演示，但仅实现一个 PE 不等于整网已在 PL 中运行。若最终改为要求整网由 PL 加速，应另行确认吞吐目标与器件资源预算。

## 2. 模型与软件参考

- 模型：单类别签名检测 YOLO26n；部署工作区使用 `models/signature_yolo26n/best_stripped.pt`。
- 最终模型固定为这份 YOLO26n 权重；完整 PL 推理范围和分阶段验收见 `pl_inference/README.md`。
- 固定输入形状：软件对照使用 `imgsz=640, rect=False`，得到 640×640。Ultralytics 默认的矩形 `predict()` 路径不能直接作为固定形状 NPU 的像素参考。
- 标准参考预处理：保持宽高比、OpenCV 线性缩放、上下补 114 灰边，再按模型接口处理 RGB 通道、张量布局和数值范围。
- 当前硬件预处理与标准参考的剩余差别是图像区域的取样方式。不能仅凭不同像素的数量判断检测精度损失。

## 3. 进入量化前的验收

1. 行为仿真输出 409,600 个像素、1 个 SOF、640 个 EOL，testbench 错误数为 0。
2. `project_1/scripts/output_check.py` 对仿真输出进行逐像素检查并通过。
3. `quantization/00_preprocess_check/check_preprocess.py` 记录当前 RTL 输入与固定 640×640 模型输入的差异。
4. 在完整验证集上比较标准预处理和当前硬件预处理的 FP32 检测结果，再决定是否保留隔行隔列取样。

当前已用新仿真输出复核第 2、3 项；第 1 项以 Vivado testbench 的 PASS 日志为准。第 4 项已在 `quantization/01_fp32_preprocess_accuracy/` 完成。验证集只有 35 张图片，结果只能代表这个验证集。

## 4. 后续 INT8 与软件仿真要求

- 校准图片的预处理必须与最终部署输入一致；记录校准数据、模型版本、量化参数与精度结果。
- INT8 权重、激活值、偏置和重定标参数应能追溯到具体模型与导出配置；导出文件使用新文件名，不覆盖训练权重。
- PE/NPU 的 Python 参考实现应明确张量布局、舍入、截断、饱和及溢出规则，再与 RTL 输出逐层比较。
- 脚本接受相对路径或参数指定路径；生成的大型临时结果放在各工作目录的 `results/` 或 `outputs/` 下。

`quantization/03_int8_ptq/` 已完成首轮卷积 W8A8 静态量化、FP32 ONNX 导出对照及保留集评估；注意力、SiLU 和检测后处理仍为浮点。35 张 RTL 验证图上，FP32+RTL 的 mAP50-95 为 0.958109，候选为 0.930091，新增漏检为 0，达到本轮预设门槛。102 个卷积的尺度、INT32 偏置及保守累加上界见被 Git 忽略的 `03_int8_ptq/results/pe_numeric_contract.json`。这些结果尚不代表 PE RTL 或整网 INT8 已实现。

后续应优先完成覆盖整张推理图的 PL 算子与调度，而非继续优化 mAP。可以牺牲吞吐量、复用少量计算单元以降低资源需求，但必须让最终检测框由 PL 完成计算。使用预制 DPU/IP 时，也要核查每个算子的位置；任何落到 PS/CPU 的推理算子都不符合此要求。
