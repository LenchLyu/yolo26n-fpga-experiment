# YOLO26n 全 PL 推理实现边界

逐阶段任务、产物和验收见 [PLAN.md](PLAN.md)；第 1、2 阶段的可执行命令见 [GETTING_STARTED.md](GETTING_STARTED.md)。

## 已确定的目标

- 固定使用当前签名检测 YOLO26n 权重与 640×640 输入；不能换成只实现部分网络的小模型。
- 从 RGB 图像转模型输入张量，直至输出最终检测框，全部模型计算由 PL 执行。PS/电脑只可装载图像、参数和指令，启动计算，读取并显示 PL 已算出的检测框。
- 当前没有开发板。本阶段以 RTL/HLS 功能仿真、目标器件 `xczu7ev-ffvc1156-2-e` 的综合与实现报告作为证据；不能据此声称实板吞吐或功耗。
- 优先实现完整功能。可以复用计算单元、降低吞吐；暂不继续追求更高 mAP 或实时帧率。

## 当前推理图的实际规模

结构来源是 `../quantization/03_int8_ptq/results/operator_manifest.json`，量化参数来源是同目录下的 `pe_numeric_contract.json`，两者均由脚本从实际 ONNX 图生成。

| 类别 | 当前图中的数量或形状 | PL 实现需要覆盖的运算 |
| --- | --- | --- |
| 卷积 | 102 个：普通 39、1×1 55、深度卷积 8 | INT8 乘加、INT32 偏置/累加、按通道重定标；共享 PE 可按层复用。 |
| 注意力 | MatMul 4、Softmax 2 | 矩阵乘、数值稳定的 Softmax 与尺度转换，必须在 PL。 |
| 激活/逐元素 | Sigmoid 88、Mul 93、Add 23 等 | SiLU、逐元素运算及广播。可用定点近似或 PL 浮点电路。 |
| 数据重排/连接 | Split 12、Concat 26、Reshape 14、Transpose 5、Resize 2 等 | 张量地址映射、复制或插值；能通过地址生成实现的操作不必配独立算术单元。 |
| 池化与检测输出 | MaxPool 3、TopK 2，另有 Gather、Slice、ReduceMax 等 | 池化、候选框解码/筛选及最终框记录。不能退回 PS 代算。 |
| 输入/输出 | `(1,3,640,640)` → `(1,300,6)` | PL 侧形成模型张量；最终输出框数、坐标、类别和分数。 |

102 个 Conv 的量化权重 initializer 合计 **2,366,640 字节**；整个 QDQ ONNX 的 initializer 数据合计 **2,510,257 字节**。它们说明权重负担可控，但不代表整网工作存储只需约 2.5 MB。单个中间张量最大为 **1,638,400 个元素**；运行时还存在同时存活的特征图、残差、注意力数据、缓存和指令。因此先按外部 DDR 存放大张量、PL 内用 BRAM/UltraRAM 分块缓存设计，实际带宽与资源要由实现报告确认。

## 最小完整实现路线

1. **锁定图与数值参考。**保存当前权重、ONNX、量化参数的哈希。为每个算子标注输入输出形状、依赖、数据格式和执行位置；执行位置必须全部是 PL。把常量与纯形状操作离线化为指令/地址参数，但不预计算任何输入相关的推理结果。
2. **搭起可复用的数据通路。**用 DDR 存放权重与较大特征图，PL 使用片上分块缓存。先完成可配置卷积/矩阵乘算术单元、地址生成、重定标与数据搬运；PS 只负责装载和启动。
3. **补全剩余算子。**依次加入逐元素激活、池化、上采样与拼接、注意力 Softmax、检测头与框筛选。每增加一类算子都用真实层张量做局部对照，避免等全图失败后才排查。
4. **全图闭环。**让 PL 仿真从一张真实 640×640 输入出发，产生可读取的检测框；电脑只负责把这些框画在图片上，并与软件参考作宽松的位置/类别核对。
5. **器件可实现性。**运行综合与布局布线，记录 LUT、FF、DSP、BRAM、UltraRAM、时序和估计带宽。没有开发板时，结果只能证明设计可仿真、可针对器件实现，不能证明实际上板运行。

已有 `../quantization/03_int8_ptq/` 完成了**卷积** W8A8 候选模型及 PE 数值检查；其中注意力和其他非卷积仍为软件浮点。该候选模型是功能参考，不是全 PL 部署文件。后续优先解决算子覆盖与数据流，精度阈值可在出现完整检测框后再收紧。
