# YOLO26n 全 PL 推理：完整工作流程

## 目标与边界

固定使用当前 YOLO26n 和 `xczu7ev-ffvc1156-2-e`。最终由 PL 从输入图像算出检测框；PS/电脑只装载图像、权重及静态指令，启动计算，读取和显示结果。当前无开发板，因此“完成”的证据是完整功能仿真与目标器件综合、实现、时序报告，不是实板运行或实测帧率。优先功能完整，允许计算单元分时复用和较低吞吐。

已完成：1280×720→640×640 RTL 图像预处理及真实图片仿真；固定输入 FP32 ONNX 导出与 `.pt` 等价性；143 张校准图生成；102 个 Conv 的 W8A8 候选量化和 PE 数值规则；35 张保留图精度验收。已有报告在 `../quantization/03_int8_ptq/results/`，该目录由 Git 忽略。

## 1. 锁定推理图和接口

**工作：**固定权重/ONNX 的 SHA-256、输入 RGB 通道顺序和数值范围、输出 `(1,300,6)` 各字段含义及阈值规则。以实际 ONNX 图生成拓扑算子表：每个节点的形状、依赖、常量、数据格式和 PL 执行单元。静态形状与常量可在电脑上编译为地址和指令；任何依赖输入图片的算术都留在 PL。

**产物：**`execution_plan`（每层配置、输入输出地址、权重位置、尺度、操作顺序）和算子覆盖表。逐项确认 Conv 102、MatMul 4、Softmax 2、Sigmoid/Mul、Resize/Concat、检测 TopK/Gather 等均有 PL 实现路径。

**通过条件：**没有“在 PS/电脑执行”的模型节点；每个中间张量能追溯生产者和使用者。此时不做新的大规模 mAP 调优。

## 2. 确定最小资源架构和内存计划

**工作：**采用少量可复用的计算单元，而非为 102 个 Conv 各建一套电路。较大权重和特征图先放在 PS 管理的 DDR，由 PL 的 AXI 主口读取；BRAM/UltraRAM 存分块缓存。做张量存活区间、缓冲复用、峰值占用和 DDR 读写量估算。定义可配置卷积/MatMul MAC 单元、逐元素/非线性单元、池化/重排单元、检测输出单元与调度控制器的职责。并行 MAC 通道数由小规模综合结果决定，不先为实时帧率优化。

**产物：**内存地址表、权重/尺度/偏置二进制文件、指令格式、模块端口图和初步资源预算。

**通过条件：**能够说明每层输入、输出和权重从哪里读、算完写到哪里；缓存不会覆盖仍要用于残差或拼接的特征图。

## 3. 打通图像流到模型张量

**工作：**将现有 `axis_resize_letterbo_0/m_axis` 接入 PL 侧输入缓冲。消费 AXI4-Stream 的 `TVALID/TREADY/TUSER/TLAST`，核查一帧 640×640；将 RGB888 像素转换成模型要求的通道布局和数值格式，写入 NPU 输入张量地址。复位、时钟和背压继续与现有 100 MHz 域保持一致，跨时钟时另做 CDC。

**产物：**输入打包模块与 testbench；一帧输出 tensor dump。

**通过条件：**按位或按已定义量化误差，与现有 Python 参考模型收到的张量一致。此阶段还不需要整网跑通。

## 4. 实现并验证卷积/矩阵乘核心

**工作：**先用真实的普通 3×3、1×1、深度卷积各一层验证同一个可配置 PE；使用已导出的有符号 INT8 权重/激活、INT32 偏置与累加、就近偶数舍入及饱和规则。随后支持 stride、padding、group、输出通道分块和 MatMul 的数据访问方式。先测算术，再测含 DDR/缓存读写的层级执行。

**产物：**可综合 PE、层级 testbench、逐元素与 `pe_numeric_contract.json` 一致的日志、单元综合资源与时序报告。

**通过条件：**三种卷积真实层输出与软件整数参考一致；MatMul 的形状、累加和输出数值规则明确。单层正确不等于整网完成。

## 5. 实现其余 PL 算子

**工作：**按网络依赖顺序补齐 Add/Mul、SiLU、MaxPool、Resize、Split/Concat、Reshape/Transpose、注意力 Softmax、检测头算术、TopK/候选框筛选。纯视图变化尽量用地址映射；真正的逐元素计算在 PL 完成。Softmax 可先采用可综合的 PL 浮点电路或定点近似，以小规模综合判断资源；不要求所有非卷积都硬改为 INT8。

**产物：**每类算子的 PL 模块、明确数值格式的快速软件参考和真实中间张量测试向量。

**通过条件：**每类算子至少有真实层输入输出对照；没有运行时 CPU 回退。无需先对 35 张图反复计算 mAP。

## 6. 执行完整网络并输出框

**工作：**用控制器按静态执行计划运行整个图，管理张量地址、残差保留、层参数切换和完成中断。PL 写出最终有效检测框的数量、坐标、类别和分数。先在 NPU 独立仿真中直接喂一张 640×640 输入；再把现有 1280×720 VDMA→预处理流接到它。独立仿真可用存储器模型代替真实 PS DDR，但被测计算必须是可综合的 PL 逻辑。

**产物：**完整仿真输出框文件、绘框预览图、与相同输入的 FP32/量化软件参考的对照。电脑上的绘图脚本只读 PL 输出的框，不代算模型层或筛框。全帧 RTL 仿真可能很慢，可减少波形记录并使用编译型仿真器；最终验证仍须覆盖真实 640×640 输入，不能只用缩小的测试图替代。

**通过条件：**至少一张真实图能由 PL 仿真输出正确类别且位置合理的框；再选少量不同图片回归。若数值不符，按首个分歧层定位，不从头反复调 mAP。

## 7. 目标器件实现与交付

**工作：**将 NPU 与现有 block design、AXI 控制/DDR 通路集成；Validate Design，运行完整综合与布局布线。检查时钟/复位、地址、DRC、LUT/FF/DSP/BRAM/UltraRAM 占用和时序。若超资源或时序不达标，优先降低并行度、分块或调整存储映射，同时保留完整算子功能。

**产物：**工程源文件、权重/指令生成脚本、可复现实验命令、仿真输出检测框、综合与实现报告、bitstream 和限制说明。

**通过条件：**目标器件实现无关键错误，资源可容纳、目标时钟时序收敛并生成 bitstream；报告如实注明没有开发板，因此未做上板功能/性能/功耗验证。[Vivado 仿真说明](https://docs.amd.com/r/2024.2-English/ug900-vivado-logic-simulation/Logic-Simulation-Overview)与[实现后检查项](https://docs.amd.com/r/2024.2-English/ug904-vivado-implementation/Recommended-Steps-After-Implementation)可作操作参考。

## 当前立刻要做的事

先做第 1 步的**完整算子覆盖表和静态执行计划**，并在第 2 步给出第一版张量内存/DDR 布局。这会决定 PE 端口、缓存大小与指令格式；在它们明确前，不直接开始堆大量 RTL，也不继续优化量化精度。
